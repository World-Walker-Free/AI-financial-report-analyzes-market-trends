# 3 分钟演示脚本（D 主讲 · D5 彩排版）

> 目标：让评委在 3 分钟内看懂「研报 → AI 抽取 → 指标 → 看板」这条链路，
> 并且**亲眼看到真实数据**，不是截图、不是静态原型。
> D5 下班前连走 3 遍；每遍用手机计时，超时就砍话术不砍画面。

---

## 演示前 30 秒（不计时，但必须做）

```bash
cd /d frontend
npm run serve          # 或 C 部署好的内网地址
```

开浏览器前逐条勾：

- [ ] `http://localhost:8080` 能打开，F12 Console **无红错**
- [ ] `.env.local` 的 `VUE_APP_DATA_SOURCE` 是本次要演示的模式（`api` 或 `planb`）
- [ ] 8 区块全部有数，不是 `--`
- [ ] 浏览器缩放 100%，分辨率 1920×1080（原型按宽屏定高，别用笔记本小窗）
- [ ] 关掉无关标签页、关掉聊天软件弹窗、F11 全屏
- [ ] 手机备好 **1 分钟录屏** + 3 张关键截图（现场服务挂了直接切）
- [ ] 让 C 确认后端在跑，让 B 确认原文链接能打开（抽查 3 条）

## 正片：3 分钟逐段脚本

### 0:00 – 0:22 ｜ 一句话讲清我们在做什么（**别念技术栈**）

**画面**：整页看板全貌，鼠标不动。

> 「我们做的事，是把每天几百份期货研报，变成一块**市场情绪看板**。
> 过去分析师要一份份翻 PDF 才能知道今天机构整体偏多还是偏空；
> 现在 AI 把每份研报读成一行结构化观点，存进数据库，算出一致性预期指数，
> 最后在这块屏上一眼看到结论。左边是走势，右边是排行，顶部是今天的家数。」

**要点**：22 秒内必须出现「研报 → AI → 指数 → 看板」四个词。不要提 Vue / ECharts / MySQL。

---

### 0:22 – 0:55 ｜ KPI + 仪表盘（讲指标口径）

**操作**：鼠标从左上「看多 4 家」缓慢划到「一致性预期指数 -14.3」，再落到仪表盘指针。

> 「今天覆盖 14 家机构：看多 4 家、看空 6 家、看平 4 家。
> 核心指标是这块仪表盘——**一致性预期指数**，
> 算法是『(看多 − 看空) / 覆盖机构数 × 100』，范围负一百到正一百。
> 今天算出来 **-14.3，指针落在绿色区间，说明机构整体偏空**。
> 这个数不是拍脑袋，是 C 那边按置信度 ≥0.6、同机构同品种去重之后算的，能用手算对上。」

**要点**：一定要报出**具体数字 -14.3** 和**公式**，这是评委最容易追问的地方。
若问「为什么分母是 14 不是研报份数」→ 答：「我们要的是机构一致性，不是报告数量，避免一家机构发 10 份把结果带偏」。

---

### 0:55 – 1:30 ｜ 观点三栏 + 原文溯源（**P0 必演**）

**操作**：点「仅看多」筛选 → 三栏只剩看多高亮 → 再切回「全部机构」→ **点一条「查看原文」**，新标签页打开研报。

> 「中间这三栏是当日机构观点，按看多、看空、看平分栏，每家机构一行。
> 关键是**可溯源**：点『查看原文』能直接打开这份研报，
> AI 给出的判断不是黑箱，每一条都能回到原文核对。
> 上方的机构筛选也能只看某一类观点。」

**要点**：**必须真的点开一次**，不能只用嘴说。打开后停 2 秒让评委看见内容，再切回看板。
⚠️ 如果 `url` 还是 `#`，这一环节直接丢分——D3 联调时就要和 B 抽查 3 条。

---

### 1:30 – 2:10 ｜ 历史表 + 组合图（演示联动，最能体现「活页面」）

**操作**：把品种从「螺纹钢」切到「铁矿石」，等全页刷新；再指历史表最后一行、指组合图蓝线。

> 「下面是近 8 个交易日的历史。表格里每一行都能和图上对上：
> 橙、灰、绿三色柱是看多、看平、看空的**家数**（左轴），
> 蓝线是一致性预期**指数**（右轴）。
> 注意刚才我切了品种，KPI、仪表盘、表格、图、排行**整页联动刷新**，
> 不是五张静态图拼在一起——前端只认 5 个接口，数据一变页面就跟着变。」

**要点**：切换动作要慢，让评委看见「整页一起变」。这是「筛选后 1 秒内联动」验收项的现场证明。
若评委问「数据哪来的」→ 答：「C 的 FastAPI 从 MySQL 读，前端通过代理调用，跨域在开发服务器上解决」。

---

### 2:10 – 2:40 ｜ 排行榜 + 底部状态栏

**操作**：鼠标扫右侧两个 TOP10，点一下排行条（触发 tooltip）。

> 「右边是按一致性指数排的看多、看空 TOP10，负值向左，一眼看出哪些品种情绪最极端。
> 底部是数据口径：区间、累计解析研报数、覆盖机构与品种数，
> 还有一句免责——观点由 AI 抽取自公开研报，**仅供研究参考，不构成投资建议**。」

**要点**：免责声明**必须念出来**，合规类问题一句话挡掉。

---

### 2:40 – 3:00 ｜ 收尾

> 「总结一下：这条链路从 9,330 份研报里先保 3/25～3/29 五个交易日，
> AI 抽取 → 入库 → 算指数 → 5 个只读接口 → 这块看板。
> 目前是 P0 范围：单品种完整演示、真实数据、可溯源；
> 品种扩展、准确率评估、内网部署属于 P1。
> 谢谢，请各位老师提问。」

**要点**：主动交代**范围裁剪**（文档第五节），别等评委问「怎么只有 5 天数据」。

## 兜底话术（背下来，别临场发挥）

| 现场状况 | 动作 | 说法 |
|---|---|---|
| 后端挂了 / 接口 500 | 页面会保留旧数据 + 顶部红条；**不要刷新** | 「这是我们的失败态设计：接口异常时保留上一次数据并提示，不让看板白屏。下面用本地快照继续演示。」→ 切 `planb` |
| 完全没网 / 服务起不来 | 放 1 分钟录屏 + 截图 | 「现场环境受限，我们提前录了同一套流程的演示视频，画面与刚才讲的是同一版数据。」 |
| 被问「AI 准确率多少」 | 交给 A | 「A 那边做了 100 份人工标注的方向一致率评估，目标是 ≥85%，这部分由他补充。」（**D 不替 A 报数**） |
| 被问「为什么用 Vue 2」 | 简短 | 「公司《软件环境汇总文档》指定 Vue + ECharts，原型按这个效果做的；CLI 5 与本机 Node 24 组合已验证可跑。」 |
| 被问「数据库/接口怎么实现」 | 交给 C | 「建表、指数幂等重算、5 个接口是 C 负责，我只消费接口；契约在 `docs/接口约定.md`。」 |
| 被问「研报怎么解析的」 | 交给 B | 「PDF/HTML 解析、去重、品种别名是 B 负责。」 |
| 数字对不上 | **别硬撑** | 「这个我现场核一下，可能是筛选条件或日期口径差异。」→ 记下来，会后查，不要编 |

> 组规：**不碰别人的活**。被问到 A/B/C 的范围就转交，别替他们答，答错了全组一起背。
